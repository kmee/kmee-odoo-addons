Brings BPMN 2.0 process diagrams into Odoo, for implementation projects
that design the solution as BPMN and validate it with the customer.

- Import a ``.bpmn`` file as it comes (diagram, colors and documentation
  of each element). Each import of the same code is a new version.
- Every task, event and gateway becomes a record, keyed by its BPMN id:
  comments (chatter), status (decided, proposal, open), design
  reference, requirements, link to the Odoo model, menu or action, and
  end-to-end test results. Comments and status survive new versions.
- A diagram viewer (bpmn-js) inside Odoo: click a task to see its panel,
  comment on it, change its status or open the Odoo screen that runs it.
  Layers: status, test results, tasks of the role of the user, original
  colors.
- Immutable version history with a semantic diff (added, removed,
  changed, moved) and a visual comparison between any two versions.
- An editor with a lock: one manager draws at a time while the others
  follow the changes live and comment.
- Three-way merge: when the diagram changed in Odoo and the file
  generated outside also changed, both are merged by BPMN id, and only
  the same property changed on both sides is a conflict for a person to
  resolve.

   Only for development or testing purpose, do not use in production.

Configuration
=============

Give users the *BPMN Processes / User* group to see diagrams and
comment, and *BPMN Processes / Manager* to import, edit, change status
and restore.

In each process, the *Lanes* tab links a lane to user groups: users of
those groups see the tasks of the lane highlighted in the *My tasks*
layer.

Usage
=====

**Import**

Processes > Import BPMN diagram: choose the ``.bpmn`` file. The code
(the file name by default) identifies the process; importing the same
code again creates a new version and lists the changes in the chatter.

Scripts can import with XML-RPC/JSON-RPC:

.. code:: python

   env["bpmn.process"].import_xml("P01_sales", xml, note="workshop 2")

The result has a ``status``: ``created``, ``updated``, ``merged``,
``unchanged``, ``conflict`` (with the list of conflicts), ``invalid``
(with the structural problems) or ``locked`` (someone is editing). Call
again with ``resolutions={"<bpmn id>:<property>": "ours" | "theirs"}``
to resolve conflicts (``ours`` is Odoo, ``theirs`` is the file).

**Documentation of each element**

The ``bpmn:documentation`` of a task is read line by line:

::

   odoo: sale.order / Sales
   sdd: 5.2 Quotation
   requisitos: COM-04, COM-10
   status: decidido | proposta | em aberto
   acao: sale.action_quotations_with_onboarding

``odoo:`` links the task to the model and menu (left empty when
ambiguous, to be filled by hand); ``acao:`` (optional) names the window
action by XML id; ``fora do sistema (...)`` marks a task done outside
Odoo. The one-line form ``Status: combinado. SDD: 6.2 V2`` is also read.
On the first import the status comes from the file; afterwards it
belongs to Odoo, and a different status in a new file is only reported
in the version changes.

**Diagram**

Open a process and click *Open diagram*. Click a task to see its panel.
Managers can change the status, and *Edit* opens the modeler with a
lock; *Save version* creates a new version. Versions can be viewed,
compared, downloaded and restored (restoring creates a new version).

**Test results**

End-to-end tests tagged ``@bpmn:<id>`` report their results with:

.. code:: python

   env["bpmn.element.test"].record_results([
       {"bpmn_id": "Task_Sales_Quote", "scenario": "quote e2e",
        "result": "passed", "environment": "hml", "process": "P01_sales"},
   ])

**Export**

*Export .bpmn* (or ``export_by_code(code)``) returns the current diagram
with the documentation and colors rewritten from the records.

Known issues / Roadmap
======================

- Simultaneous editing by several people (CRDT over the Odoo bus) is not
  included: the editor works with a lock. It needs an experiment with
  real diagrams first.
- Customers comment as internal users; portal access is not included.
- The editor has no properties panel: status, references and links are
  edited in the side panel and in the element form, and written back to
  the documentation on export.
- bpmn-js 17.11.1 is bundled in ``static/lib/bpmn-js`` (MIT license; the
  bpmn.io watermark must stay visible on the diagram).
